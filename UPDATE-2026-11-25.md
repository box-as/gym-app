# RepState: progress at your own pace

Program weeks now advance after all movements in the active week are complete or explicitly skipped, with at least one completed movement. Time away never skips program weeks. Existing saved active weeks are respected; an account without one resumes from the latest week with logged or marked workout activity. Browsing another week does not change the current week. Existing logs, check-ins, dates, milestones and the legacy start-date setting are not cleared or moved.

A session's first logged load/reps, copied working sets, or finished workout stores the device-local date. Existing saved dates, including deliberate empty records, are never silently replaced. Use the collapsed **Edit date** control for a correction. No date is guessed from the old start date for unsaved historical suggestions.

Week 44 remains complete at the cycle end. Automatic reuse of Week 1 is intentionally disabled: existing IDs do not distinguish different cycles, and reusing them would overwrite prior history. The four training blocks and deload prescriptions are unchanged.

Deploy only to the existing RepState application from `box-as/gym-app` using the dedicated repository-limited GitHub app. Before any production deploy, take a consistent SQLite backup and preserve the existing persistent `/data` volume, account data, environment and hostname. Do not import test data or replace the database. The source archive is deployable but is not proof of live deployment.

Test with `node --check public/app.js`, `node tests/repstate_frontend.test.js` and `python3 tests/server_integration_test.py`. Server tests use disposable accounts and a temporary SQLite database.
