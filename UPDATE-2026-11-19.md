# RepState: saved current week

In Training log, choose a week and tap **Set selected as current**. The **Current week** button returns to that saved choice, and the displayed current week is used throughout the app. The saved week stays fixed until it is changed manually or **Use start-date week** is selected; it does not advance automatically. Viewing another week does not change the saved current week.

The setting is kept in the existing account-specific synced settings, so it works on the user's signed-in devices. When not signed in, it remains local to the browser. Accounts without an override retain the existing start-date calculation. Selecting or clearing an override does not change the program start date, workout logs, check-ins, session dates, or other accounts. The normal sync process merges the setting with other existing data. No database schema migration or shared default Week 5 is introduced.

This source is based on `box-as/gym-app` main commit `5ccc2fa2a145452c44bc9526998133b426f2bf7b`, including the existing extra sets, previous-week logging, volume and session-date features. `UPDATE-2026-10-21.md` is a historical record of an earlier bundle and its status at that time, not the deployment status of this update.

## Deployment

Back up the production SQLite database using a consistent SQLite backup before upgrading. Apply the changes to the existing `box-as/gym-app` main branch and allow the existing Coolify resource to deploy, preserving its persistent `/data` mount, environment variables, hostname, and account configuration. Never replace the database with a development database or remove its volume.

After deployment, sign in to the intended account, open Training log, choose Week 5, and tap **Set selected as current**. Navigate to another week and tap **Current week** to verify it returns to Week 5. Check that the original start date and prior workouts/check-ins are still present. This action must be performed separately for each account; it does not alter other users.

Run checks with `node --check public/app.js`, `node tests/repstate_frontend.test.js`, and `python3 tests/server_integration_test.py`. The server tests use disposable accounts and an isolated temporary SQLite database.
